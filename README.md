# OpenJ9 for iOS

OpenJ9 Java 21 interpreter port for embedding in an iOS application. Targets arm64 iOS devices and arm64 iOS Simulator, minimum iOS 15.0. Sources are pinned to IBM Semeru 21.0.13.0 / Eclipse OpenJ9 0.63.0 in `sources.env`.

**Validation status:** the iOS port is under build validation. No device runtime or App Store approval is claimed. Use the build workflow's logs and Simulator smoke result—not the presence of an XCFramework—as evidence that a revision works.

## Build

Requires an Apple Silicon Mac with Xcode and the iOS SDKs. The GitHub Actions workflow uses `macos-15` runners.

```sh
brew install autoconf ccache cmake bash make xcodegen
git clone https://github.com/stardewjames/openj9-ios.git
cd openj9-ios
export PATH="$(brew --prefix make)/libexec/gnubin:$PATH"
scripts/fetch-sources.sh
scripts/build-jdk.sh iphoneos
scripts/build-jdk.sh iphonesimulator
```

The build script downloads and verifies the matching macOS Semeru JDK used for `javac`, `jmod` and `jlink`. Target executables are not used as the build JDK. OpenJ9's small build-time generators use the host-exec adapter in the JDK patch.

For each SDK, turn the resulting jmods into frameworks:

```sh
for sdk in iphoneos iphonesimulator; do
  scripts/package-runtime.sh --sdk "$sdk" \
    --jmods "work/src/jdk/build/ios-$sdk/images/jmods" \
    --jlink "$PWD/work/semeru/home/bin/jlink" --out out/runtime --version 21.0.13
done
scripts/make-xcframeworks.sh \
  --device out/runtime/iphoneos/Frameworks \
  --simulator out/runtime/iphonesimulator/Frameworks \
  --out Artifacts/XCFrameworks
scripts/generate-package.sh --frameworks-dir Artifacts/XCFrameworks
scripts/smoke-test-simulator.sh
```

The local Swift package requires the generated `Artifacts/XCFrameworks` directory. Released binary packages need the release URLs/checksums generated by `scripts/generate-package.sh`; cloning sources alone does not download unbuilt binaries.

## Embed

See [the embedding guide](docs/EMBEDDING.md) and `Samples/HelloJava` for the Objective-C/Swift API, Java classpath setup and JNI access.

Every native library is an individual framework. The real OpenJ9 VM is `jvm.framework/jvm`; its read-only Java home is bundled at `jvm.framework/javahome`. The framework packager rewrites Mach-O dependencies and install names. Xcode signs frameworks when embedding them in the host app.

## Platform constraints

- Interpreter only: JIT and AOT code generation are disabled, including when `-Xjit` is requested.
- Headless `java.desktop`: software Java2D, image codecs and file-backed font rendering. No native AWT windows, screen capture or system printing.
- No child processes, Attach API, shared-class cache or fork-based system dumps.
- Java 21 Foreign Function & Memory upcall stubs require generated executable code and are unsupported. JNI and interpreted Java use static native code.
- iOS owns application lifetime and background execution. A VM does not bypass suspension or jetsam; set a conservative heap maximum.
- One VM per process; `System.exit` and fatal VM errors can terminate the host app.
- Device builds are not device execution tests. Signed physical-device validation requires an Apple provisioning profile and a device.

Interpreter-only execution is **not** an App Store acceptance guarantee. Host applications must comply with public API, code-signing, privacy, licensing and App Review rules, including restrictions on downloaded executable functionality. The included privacy manifest must be reviewed against the host application's actual use.

## Upstream patches

`patches/openjdk.patch`, `patches/openj9.patch` and `patches/omr.patch` are applied to the pinned revisions by `scripts/fetch-sources.sh`. The script refuses mismatched or non-repository destinations and preserves existing local edits.

For development, separate clones can be kept in `upstream/openjdk`, `upstream/openj9`, and `upstream/omr`; use `scripts/export-patches.sh` to export edits. For the nested build layout, pass all three source directory paths explicitly.

Upstream Java/OpenJ9/OMR code retains its upstream licenses, including applicable Classpath/Assembly exceptions. Distributing a runtime requires preserving its notices and satisfying the corresponding source-license obligations.
